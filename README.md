# فاتورة - مركز الودق

تطبيق فواتير كامل: تسجيل دخول (أدمن وموظفين)، قائمة أجهزة (استيراد/تصدير Excel)، تكوين فاتورة تلقائي بالاعتماد على مبلغ مستهدف، تتبع الواصل/الآجل، سجل فواتير، وتوليد PDF حقيقي من الخادم.

## البنية

```
server/          كود الخادم (Express + SQLite)
client/          واجهة React (تُبنى وقت النشر)
Dockerfile       يبني الواجهة ثم يشغّل الخادم مع Chromium لتوليد PDF
docker-compose.yml
```

## الخطوة 1: الرفع على GitHub

```bash
git init
git add .
git commit -m "Initial commit"
```

أنشئ مستودع جديد (فارغ، بدون README) على github.com، ثم:

```bash
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git branch -M main
git push -u origin main
```

**تحقق قبل الدفع**: تأكد أن ملف `.env` غير موجود ضمن الملفات المرفوعة (`.gitignore` يستثنيه تلقائيًا) — لا تضع كلمات مرور حقيقية بأي ملف يُرفع لمستودع عام.

## الخطوة 2: إنشاء الخدمة في Dokploy

1. من لوحة Dokploy: **Projects** → أنشئ مشروع جديد (أو اختر موجود).
2. **Create Service** → اختر **Compose**.
3. اربطه بمستودع GitHub الذي رفعته للتو (Dokploy يطلب صلاحية وصول إذا كان المستودع خاصًا).
4. تأكد أن مسار ملف الكومبوز هو `docker-compose.yml` (موجود بالجذر أصلًا، القيمة الافتراضية عادة صحيحة).

## الخطوة 3: متغيرات البيئة (مهم)

من تبويب **Environment** بنفس الخدمة، أضف:

```
JWT_SECRET=<القيمة المرسلة لك بالمحادثة>
DEFAULT_ADMIN_PASSWORD=<القيمة المرسلة لك بالمحادثة>
```

**لا تضع هذه القيم داخل أي ملف يُرفع لـ GitHub** — هذا بالضبط سبب وجود خطوة منفصلة لها بلوحة Dokploy، حتى لو كان المستودع خاصًا.

## الخطوة 4: الدومين وSSL

من تبويب **Domains** بالخدمة، أضف الدومين (الفرعي المجاني من Hostinger أو أي دومين تملكه)، ووجّه سجل DNS من نوع A لعنوان السيرفر. Dokploy يفعّل شهادة SSL مجانية (Let's Encrypt) تلقائيًا بعد التحقق من الدومين.

## الخطوة 5: النشر

اضغط **Deploy**. أول مرة تستغرق وقتًا أطول (تثبيت الحزم + تحميل Chromium بالصورة). راقب السجلات (Logs) لغاية ما تشوف:

```
فاتورة - مركز الودق: يعمل على المنفذ 3000
```

## أول تسجيل دخول

```
اسم المستخدم: admin
كلمة المرور: (القيمة اللي وضعتها بـ DEFAULT_ADMIN_PASSWORD)
```

**غيّرها فورًا** من تبويب «بيانات المحل» → «تغيير كلمة المرور» بعد أول دخول.

## إدارة الموظفين

حساب الأدمن فقط يشوف تبويب «الموظفون» — منه تضيف حسابات موظفين (اسم مستخدم + كلمة مرور + اسم كامل)، وتقدر تصفّر كلمة مرور أي موظف بأي وقت. كل فاتورة تُحفظ مربوطة باسم الموظف اللي أنشأها، ويظهر بعمود «أنشأها» بالسجل.

## ثبات البيانات

قاعدة البيانات (SQLite) محفوظة داخل الحجم (volume) المسمى `invoice_data`، خارج الحاوية — يبقى سليمًا حتى لو أعدت النشر (Redeploy) أو حدّثت الكود. **لا تحذف هذا الـ volume** إلا إذا تريد تصفير البيانات فعلًا.

## استكشاف الأخطاء

**فشل توليد PDF (خطأ 500 من `/api/pdf`)**: افتح سجلات الحاوية. الأسباب الشائعة:
- Chromium ما نصب صح بالصورة — تأكد إن مرحلة البناء (`docker build`) نجحت بالكامل بدون أخطاء بخطوة `apt-get install`.
- الذاكرة قليلة على الـ VPS (Puppeteer يحتاج ذاكرة كافية وقت التوليد). إذا خطتك على Hostinger أقل من 2GB RAM، جرّب ترقيتها.
- إذا استمرت المشكلة رغم ذلك، البرنامج يتراجع تلقائيًا لفتح نافذة طباعة المتصفح كحل بديل، فالمستخدم ما يبقى بدون خيار.

**"JWT_SECRET environment variable is not set"**: نسيت إضافة المتغير بالخطوة 3 — أضفه من لوحة Dokploy وأعد النشر.

**تسجيل الدخول ما يشتغل بعد النشر بدومين جديد**: تأكد إن الدومين شغّال فعليًا بـ HTTPS (وليس HTTP)، لأن الكوكي المستخدمة بتسجيل الدخول تتطلب اتصال آمن بالإنتاج.
